# Утилита statforge

Утилита statforge предназначена для обработки бинарных данных, представленных в виде массивов струткур StatData:
```c
typedef struct StatData { 
    long  id; 
    int   count; 
    float cost; 
    unsigned int primary:1; 
    unsigned int mode:3; 
} StatData; 
```
## Аргументы 
* два пути до двух файлов c бинарными данными; 
* путь до файла результата.
```bash
    # напрмер
    statforge data1 data2 result 
``` 
## Алгоритм работы
* Считываем файлы (пути указаны в первых двух аргументах); 
* Объединяем содержимое файлов (JoinDump):
    * в результате id всех записей уникален
    * При объединении записей с одинаковым id поля count и cost складываются, поле primary будет иметь значение 0, если хотя бы в одном из элементов оно было 0. Поле mode имеет максимальное значение из двух представленных. 
* Сортируем содержимое (SortDump); 
* Печатаем первые 10 записей в виде таблицы;
    При этом значения должны иметь формат: 
    * id в шестнадцатеричном виде; 
    * count в десятичном виде; 
    * cost в научном/экспоненциальном формате c 3 знаками после запятой (123 -> '1.230e+02'); 
    * primary нужно печатать "n" если оно 0 и "y" если оно 1; 
    * mode в бинарном формате ( 5 -> '101');
    ```c
    // например:
    0x000000000b111a3f          42  1.234e+02  y  101
    0x000000000000007c         127  5.678e+03  n  001
    ```
* Сохраняем файл, по пути, который указан в 3 аргументе.


## Тест-кейсы для утилиты Statforge

Ниже представлено подробное описание тест-кейсов для проверки утилиты `statforge`. Каждый тест-кейс включает название, цель, входные данные, ожидаемый результат и проверяемый аспект функциональности.

#### **TC-01: Базовый сценарий из технического задания**
**Цель:** Проверить корректность работы утилиты на примере из ТЗ.
**Входные данные:**
- Файл A: `{id:90889, count:13, cost:3.567, primary:0, mode:3}`, `{id:90089, count:1, cost:88.90, primary:1, mode:0}`
- Файл B: `{id:90089, count:13, cost:0.011, primary:0, mode:2}`, `{id:90189, count:1000, cost:1.00003, primary:1, mode:2}`
**Ожидаемый результат (после Join + Sort):**
- `{id:90189, count:1000, cost:1.00003, primary:1, mode:2}`
- `{id:90889, count:13, cost:3.567, primary:0, mode:3}`
- `{id:90089, count:14, cost:88.911, primary:0, mode:2}`
**Проверяет:** Полный цикл работы: загрузка, объединение, сортировка, сохранение, форматированный вывод.

#### **TC-02: Оба входных файла пусты**
**Цель:** Проверить обработку пустых файлов.
**Входные данные:** Два файла с 0 записей (корректный заголовок, но пустое тело).
**Ожидаемый результат:**
- JoinDump возвращает пустой массив
- SortDump корректно обрабатывает пустой массив
- Программа выводит сообщение об отсутствии данных (или ничего не выводит)
- В выходной файл сохраняется корректный заголовок с 0 записей
**Проверяет:** Устойчивость к нулевой длине массивов.

#### **TC-03: Один файл пуст, второй содержит данные**
**Цель:** Проверить объединение с пустым массивом.
**Входные данные:** Файл A пуст, Файл B содержит 5 произвольных записей.
**Ожидаемый результат:** Результат идентичен содержимому файла B (после сортировки).
**Проверяет:** Корректность JoinDump при работе с  пустыми массивами.
:** Производительность и потребление памяти.

#### **TC-04: Полное отсутствие дубликатов ID**
**Цель:** Проверить, что при отсутствии пересечений все записи сохраняются.
**Входные данные:** Файл A: ID 1,2,3; Файл B: ID 4,5,6.
**Ожидаемый результат:** В результате 6 записей с ID 1,2,3,4,5,6. Значения полей переносятся без изменений.
**Проверяет:** Базовое объединение без коллизий.

#### **TC-05: Один ID повторяется многократно**
**Цель:** Проверить суммирование при множественных дублях.
**Входные данные:** Файл A: ID=5 (count=1), ID=5 (count=2); Файл B: ID=5 (count=3), ID=5 (count=4).
**Ожидаемый результат:** Одна запись с ID=5, count=10 (1+2+3+4).
**Проверяет:** Корректное суммирование при многократных повторах.

#### **TC-06: Правило для поля primary (приоритет 0)**
**Цель:** Проверить, что primary становится 0, если хотя бы в одной записи он 0.
**Входные данные (все с одинаковым ID):**
- Вариант A: primary=1 + primary=1 → результат primary=1
- Вариант B: primary=1 + primary=0 → результат primary=0
- Вариант C: primary=0 + primary=0 → результат primary=0
- Вариант D: primary=1 + primary=1 + primary=0 → результат primary=0
**Проверяет:** Логику битового поля primary.

#### **TC-07: Правило для поля mode (максимальное значение)**
**Цель:** Проверить выбор максимального mode.
**Входные данные (все с одинаковым ID):**
- Вариант A: mode=2 + mode=5 → результат mode=5
- Вариант B: mode=3 + mode=3 → результат mode=3
- Вариант C: mode=0 + mode=7 → результат mode=7
- Вариант D: mode=1 + mode=2 + mode=4 → результат mode=4
**Проверяет:** Логику выбора максимального значения mode.

#### **TC-08: Комбинированная логика (count, cost, primary, mode)**
**Цель:** Проверить одновременное применение всех правил.
**Входные данные (три записи с ID=100):**
- Запись 1: count=5, cost=10.0, primary=1, mode=2
- Запись 2: count=3, cost=20.0, primary=0, mode=5
- Запись 3: count=2, cost=30.0, primary=1, mode=1
**Ожидаемый результат (для ID=100):**
- count = 5+3+2 = 10
- cost = 10.0+20.0+30.0 = 60.0
- primary = 0 (так как есть 0)
- mode = 5 (максимум из 2,5,1)
**Проверяет:** Комплексную логику объединения.

#### **TC-09: Сортировка уже отсортированного массива**
**Цель:** Проверить стабильность (или нестабильность) сортировки.
**Входные данные:** Массив, уже отсортированный по возрастанию cost.
**Ожидаемый результат:** Порядок элементов не изменяется.
**Проверяет:** Корректность алгоритма сортировки.

#### **TC-10: Сортировка обратного порядка**
**Цель:** Проверить полную пересортировку.
**Входные данные:** Массив, отсортированный по убыванию cost.
**Ожидаемый результат:** Массив становится отсортированным по возрастанию cost.
**Проверяет:** Способность алгоритма обрабатывать наихудший случай.

#### **TC-11: Все значения cost равны**
**Цель:** Проверить поведение при одинаковых ключах сортировки.
**Входные данные:** Массив из 10 записей с одинаковым cost.
**Ожидаемый результат:** Программа не зависает, не падает. Изменение порядка допускается (если сортировка нестабильная).
**Проверяет:** Устойчивость к вырожденным случаям.

#### **TC-12: Отрицательные и нулевые значения cost**
**Цель:** Проверить сортировку с отрицательными числами.
**Входные данные:** cost = [-5.0, 0.0, 3.0, -10.0, 2.0]
**Ожидаемый результат:** [-10.0, -5.0, 0.0, 2.0, 3.0]
**Проверяет:** Корректную работу с плавающей точкой и знаками.
