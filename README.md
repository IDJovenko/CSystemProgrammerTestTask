# Утилита statforge

Утилита statforge предназначена для обработки бинарных данных, представленных в виде массивов струткур StatData:
```c
typedef struct StatData { 
    long  id; 
    int   count; 
    float cost; 
    unsigned int primary:1; 
    unsigned int mode:3; 
} StatData; 
```
## Аргументы 
* два пути до двух файлов c бинарными данными; 
* путь до файла результата.
```bash
    # напрмер
    statforge data1 data2 result 
``` 
## Алгоритм работы
* Считываем файлы (пути указаны в первых двух аргументах); 
* Объединяем содержимое файлов (JoinDump):
    * в результате id всех записей уникален
    * При объединении записей с одинаковым id поля count и cost складываются, поле primary будет иметь значение 0, если хотя бы в одном из элементов оно было 0. Поле mode имеет максимальное значение из двух представленных. 
* Сортируем содержимое (SortDump); 
* Печатаем первые 10 записей в виде таблицы;
    При этом значения должны иметь формат: 
    * id в шестнадцатеричном виде; 
    * count в десятичном виде; 
    * cost в научном/экспоненциальном формате c 3 знаками после запятой (123 -> '1.230e+2'); 
    * primary нужно печатать "n" если оно 0 и "y" если оно 1; 
    * mode в бинарном формате ( 5 -> '101');
    ```c
    // например:
    0x00001a3f          42  1.234e+2  y                      101
    0x0000007b         127  5.678e+3  n                     1101
    ```
* Сохраняем файл, по пути, который указан в 3 аргументе.


# Утилита testforge

Утилита testforge предназначена для тестирования утилиты statforge

## Принцип работы
* Формирует файлы данных для утилиты обработки данных (из массивов данных определённых в ней в качестве констант); 
* Запусткает утилиту обработки данных; 
* Считывает результат обработки и сравнивает его с эталонными данными (константами в памяти утилиты тестирования); 
* При расхождении ожидаемого результата с полученным печатает сообщение об ошибке в `stderr`; 
* При успешном прохождении теста печатает отчёт о времени выполнения тестов и списке пройдённых тестов в `stdout`.

## Краевые случаи утилиты `statforge`

Данный раздел описывает набор тестовых сценариев, разработанных для всесторонней проверки утилиты обработки бинарных данных `statforge`. Тесты охватывают штатные режимы работы, граничные условия и ошибочные ситуации.

### 1. Работа с файловой системой и вводом-выводом (I/O)

Базовые тесты на корректность взаимодействия с файловой системой.

| Название теста            | Действие                                                                                              | Ожидаемый результат                                                                                                |
| ------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **Несуществующий входной файл**   | Передача путей к файлам, которые не существуют.                                                       | Программа завершается с ошибкой (код возврата `1`), выводя в `stderr` сообщение: `"Ошибка: файл 'путь' не найден"`. |
| **Отсутствие прав на чтение**      | Создание файла и снятие прав на чтение (`chmod 000 filename`).                                        | Программа завершается с ошибкой и сообщением: `"Ошибка: недостаточно прав для чтения файла 'путь'"`.                 |
| **Отсутствие прав на запись**      | Попытка сохранения результата в директорию без прав на запись (например, `/root/`).                   | Программа завершается с ошибкой и сообщением: `"Ошибка: не удается создать/записать файл по пути 'путь'"`.           |
| **Выходной файл уже существует**   | Запуск утилиты с путем к файлу, который уже существует.                                                | Файл корректно перезаписывается без предупреждения (стандартное поведение Unix-утилит).                              |
| **Слишком длинный путь к файлу**   | Передача пути, длина которого превышает `PATH_MAX`.                                                   | Ошибка открытия файла.                                                                                             |

### 2. Граничные значения длины массивов

Проверка работы с массивами данных в допустимом диапазоне длин (от 0 до 100000 записей).

| Название теста                  | Действие                                                                                           | Ожидаемый результат                                                                                                                                                                                                                              |
| ------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Оба файла пусты**             | Создание двух корректных (с точки зрения формата `StoreDump`), но пустых файлов.                   | 1. `JoinDump` возвращает пустой массив.<br>2. `SortDump` от пустого массива выполняется без ошибок.<br>3. Программа информирует об отсутствии данных для вывода.<br>4. Результирующий файл содержит `0` записей.                                     |
| **Один файл пуст**              | Файл `A` пуст, файл `B` содержит N записей.                                                         | Результат обработки идентичен содержимому файла `B` (после сортировки).                                                                                                                                                |
| **Максимальный размер**         | Генерация двух файлов, каждый из которых содержит ровно 100000 записей.                               | 1. Программа не вызывает ошибок, связанных с нехваткой памяти (Out-Of-Memory).<br>2. Время выполнения остается в приемлемых пределах (тест производительности).                                                                                      |

### 3. Некорректный формат входных данных

Проверка устойчивости функции `LoadDump()` к поврежденным данным.

| Название теста                     | Действие                                                                                                                                 | Ожидаемый результат                                                                                                                    |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **Файл меньшего размера**    | Создание файла, в заголовке которого указано наличие 100 записей, но физический размер файл позволяет прочитать только 50.               | Функция `LoadDump` обнаруживает несоответствие и возвращает ошибку: `"Файл поврежден: неожиданный конец файла"`.                         |
| **Поврежденные данные в середине файла** | Создание корректного файла с последующим бинарным редактированием (порчей) нескольких байт в середине одной из записей. | Программа не должна завершаться критической ошибкой (крахом). Желательно обнаружение некорректных данных.                                  |

### 4. Логика обработки данных (JoinDump)

Проверка корректности алгоритма объединения записей с одинаковыми `id`.

| Название теста                               | Действие                                                                                                                              | Ожидаемый результат                                                                                                                                                                                                                              |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Полное отсутствие дубликатов `id`**        | Входные массивы не имеют общих идентификаторов.                                                                                       | Результирующий массив содержит все записи из обоих файлов.                                                                                                                                                                                           |
| **Множественные дубликаты `id`**             | Один и тот же `id` встречается многократно: несколько раз в пределах одного файла и несколько раз в другом файле.                       | В результате формируется одна запись с данным `id`, в которой `count` и `cost` являются *суммой* значений всех соответствующих полей из всех записей-дублей.                                                                                        |
| **Правило для поля `primary` (приоритет 0)** | Наличие записей с одинаковым `id`, где у одной `primary = 1`, а у другой `primary = 0`.                                               | Итоговое поле `primary` устанавливается в `0`.                                                                                                                                                                                                      |
| **Правило для поля `mode` (поиск максимума)** | Наличие записей с одинаковым `id` и разными значениями `mode`, например `2` и `5`.                                                    | Итоговое поле `mode` устанавливается в *максимальное* из всех значений (в примере — `5`).                                                                                                                                                           |
| **Переполнение при сложении `count`**        | Создание большого числа дублей одного `id`, чтобы сумма значений `count` превысила максимальное значение для типа `int` (2,147,483,647). | Программа должна продемонстрировать обработку этой ситуации: либо использовать беззнаковый тип, либо выполнять проверку на переполнение. Недопустимо неопределенное поведение (отрицательные значения, краш). |
| **Потеря точности при сложении `cost`**      | Сложение чисел с очень разным порядком (например, `1e30` и `1e-30`).                                                                  | Меньшее число может быть потеряно ввиду ограниченной точности типа `float`. Результат должен быть предсказуем и находиться в пределах допустимой погрешности.                                                                                          |

### 5. Логика обработки данных (SortDump)

Проверка корректности сортировки по полю `cost`.

| Название теста                       | Действие                                                                                         | Ожидаемый результат                                                                                                                              |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Сортировка уже отсортированного массива** | На вход подается массив, уже отсортированный по возрастанию `cost`.                                 | Порядок элементов не изменяется.                                                                                                                    |
| **Сортировка обратного порядка**     | На вход подается массив, отсортированный по убыванию `cost`.                                     | Массив становится отсортированным по возрастанию `cost`.                                                                                             |
| **Все значения `cost` равны**        | Все элементы массива имеют одинаковое значение поля `cost`.                                      | Программа не зависает и не падает. Изменение порядка элементов допускается, если сортировка не является стабильной (требования к стабильности в ТЗ нет). |
| **Отрицательные и нулевые значения** | Массив содержит отрицательные числа, ноль и положительные числа в поле `cost`.                   | Сортировка выполняется корректно: отрицательные числа располагаются перед нулем, ноль — перед положительными.                                         |

### 6. Форматированный вывод

Проверка соответствия формата вывода первых 10 записей требованиям технического задания.

| Название теста        | Действие                                 | Ожидаемый результат                                          |
| --------------------- | ---------------------------------------- | ------------------------------------------------------------ |
| **Формат `mode`**     | Вывод значений `mode = 0`, `mode = 5`.   | `"0"`, `"101"` соответственно.                               |
| **Формат `cost`**     | Вывод значений `123.0` и `0.00000123`.     | `"1.230e+2"` и `"1.230e-6"`.           |
| **Формат `id`**       | Вывод значения `id = 0xABC`.             | Шестнадцатеричное представление в нижнем регистре: `"abc"`. |
| **Формат `primary`**  | Вывод значений `0` и `1`.                | `"n"` и `"y"` соответственно.                               |
